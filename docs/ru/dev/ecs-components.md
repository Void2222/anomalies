# 🧩 Справочник ECS-компонентов (ECS Components)

Вся прикладная логика поведения аномалий вынесена в независимые компоненты, реализующие интерфейс `IAnomalyComponent` (наследник `ILightComponent` движка `LightEntity`).

Контейнер аномалии (`LightAnomalyInstance`) исполняет компоненты через 0-allocation snapshot массив:
- На сервере: `comp.serverTick(anomaly)`
- На клиенте: `comp.clientTick(anomaly)`

---

## 📋 Базовый контракт (`IAnomalyComponent`)

```java
public interface IAnomalyComponent extends ILightComponent {
    default void serverTick(IAnomalyHolder anomaly) {}
    default void clientTick(IAnomalyHolder anomaly) {}
    default void save(CompoundTag tag) {}
    default void load(CompoundTag tag) {}
}
```

---

## 1. ⚔️ `DamageComponent`
Отвечает за периодическое и зонированное нанесение урона сущностям.

- **Источники урона:** Поддерживает типы `fire`, `lightning`, `magic`, `generic`.
- **Защита от Friendly Fire:** Проверяет список игнорируемых игроков (`AnomalyIgnoreManager.isIgnored(player)`). Если игрок в списке, урон полностью аннулируется до любых расчетов.
- **Интеграция с Forge Events:** Публикует событие `AnomalyDamageEvent`. Аддоны могут изменить финальный урон или отменить событие (`@Cancelable`).
- **Поддержка огня:** Если в конфигурации зоны задан `fireSeconds > 0`, сущность поджигается.

---

## 2. 🧲 `ImpulseComponent`
Реализует векторную физику: втягивание в эпицентр, круговое вращение (вихрь) и вертикальный подброс.

- **Втягивание (`pullForce`):** Рассчитывает вектор смещения от сущности к центру аномалии с нормализацией.
- **Вращение (`spinForce`):** Векторное произведение вектора направления на вертикаль (`Vec3(0, 1, 0)`), закручивающее сущность по орбите вокруг центра.
- **Вертикальный импульс (`impulseY`):** Добавляет подброс по оси Y.
- **Отслеживание перехода зон:** Хранит историю `entityZones (UUID -> ZoneConfig)`. При пересечении границы зон стреляет событием `AnomalyZoneTransitionEvent`.
- **Защита игнорируемых игроков:** Если `AnomalyIgnoreManager.isIgnored(player) == true`, импульсы не прикладываются.

---

## 3. ✨ `ParticleComponent`
Клиентский компонент генерации визуальных частиц с двухуровневой оптимизацией производительности.

- **Формы спавна:**
  - `SPHERE`: Объёмная сфера с алгоритмом Rejection Sampling.
  - `CYLINDER`: Цилиндрическая колонка.
  - `DISC`: Плоский горизонтальный диск.
- **Оптимизация Уровень 1 (LOD Distance):** Если дистанция до камеры $> 70$ блоков ($4900$ блоков²), рендер мгновенно прерывается.
- **Оптимизация Уровень 2 (Frustum Culling):** Проверяет пересечение AABB аномалии с усечённой пирамидой видимости камеры игрока (`Frustum`). Если аномалия за спиной — частицы не спавнятся.
- **Оптимизация Уровень 3 (Occlusion Culling):** Интервальный рейкаст раз в 8 тиков (`ClipContext.Block.VISUAL`). Если аномалия полностью перекрыта глухими непрозрачными блоками (камни, земля), спавн частиц отключается. Через прозрачные блоки (стекло, лёд) луч проходит свободно.

---

## 4. 🔊 `SoundComponent`
Пространственное позиционное воспроизведение звуков с плавающим интервалом.

- **Случайный таймер:** Рассчитывает следующий тик воспроизведения из диапазона `[min, max]`.
- **Затухание по дистанции:** Поддерживает `minDistance` и `maxDistance`.

---

## 5. 🎯 `TriggerComponent`
Детектор приближения сущностей с поддержкой спящего режима (LOD).

- **Спящий режим (Sleeping LOD):** Каждые `checkInterval` тиков проверяет, есть ли игроки в радиусе 48 блоков. Если игроков рядом нет — детальный поиск по AABB отключается, экономя такты CPU.
- **Фильтрация:** Проверяет живых сущностей и предметы, отсекает игроков из списка `AnomalyIgnoreManager`.

---

## 6. 🧲 `SnapToGridComponent`
При спавне или загрузке выравнивает центр аномалии по сетке блоков: `X.5`, `Y.0`, `Z.5`. Срабатывает однократно на первом серверном тике.

---

## 7. 🔄 `StateMachineComponent`
Оркестратор состояний и фазовых переходов на основе скомпилированных моделей `.anom` (`AnomalyScriptModel`).

- Каждый тик запрашивает условия переходов у текущего состояния.
- При смене фазы:
  1. Вызывает `onExit` предыдущего состояния.
  2. Очищает временные кэшированные ивенты в `TransientZoneCache`.
  3. Перестраивает компоненты аномалии через `ZoneFactory.applyComponents(...)`.
  4. Рассылает синхронизацию клиентам через `LightEntityTracker.syncEntity(...)`.

---

## 8. 🧪 `RecipeProcessorComponent`
Обработчик физических рецептов крафта предметов, брошенных в аномалию.

- **Виртуальное бронирование (Reservation):** Чтобы два рецепта не забрали один и тот же предмет, сущности предметов (`ItemEntity`) резервируются по UUID в сессии крафта.
- **Тайминг варки:** Прогресс крафта тикает каждый такт. По завершении исходные предметы поглощаются (`itemEntity.discard()`), а результат выбрасывается в мир со спецэффектами.
