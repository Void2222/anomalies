# 📜 Регламент Технических Заданий (TZ / Specifications)

Папка `.agents/tz/` предназначена для хранения технических заданий, спецификаций фич и архитектурных планов разработки.

---

## 📌 Конвенция именования файлов

Все файлы ТЗ в этой директории должны строго следовать следующему контракту:

```text
TZ-<НОМЕР>-<ГГГГ-ММ-ДД-ЧЧ-мм>-<КОРОТКОЕ_НАЗВАНИЕ_НА_АНГЛИЙСКОМ>.md
```

### Правила:
1. **Префикс:** `TZ-` (всегда заглавными буквами).
2. **Номер:** трёхзначный порядковый номер с ведущими нулями: `001`, `002`, `003`...
3. **Таймстемп старта:** дата и время начала с понятным дефисным разделением: `YYYY-MM-DD-HH-mm` (год-месяц-день-часы-минуты). Читается легко и не сливается в кашу из цифр!
4. **Слаг/Название:** краткое наименование фичи в `kebab-case` (строчные латинские буквы, слова через дефис).
5. **Расширение:** `.md`.

### Примеры правильных названий:
- `TZ-001-2026-10-25-21-55-visual-node-graph-editor.md`
- `TZ-002-2026-10-26-14-30-spatial-sound-occlusion.md`
- `TZ-003-2026-10-27-09-15-anomaly-crafting-chamber.md`

---

## 📋 Обязательная структура документа ТЗ:
1. **Заголовок и метаданные:** Номер, статус (DRAFT / IN_PROGRESS / DONE), автор, дата.
2. **Цель и контекст:** Зачем фича нужна, какую проблему решает.
3. **Архитектурное решение:** Диаграммы, разбиение на компоненты, модели данных.
4. **Пошаговый план реализации:** Разбиение на спринты/шаги.
5. **Критерии приёмки (Definition of Done):** Что именно должно работать для закрытия задачи.

---

## 🚫 Строгое правило закрытия чекбоксов (Definition of Done Rule):
> [!CAUTION]
> **ЗАПРЕТ НА САМОВОЛЬНУЮ ОТМЕТКУ ЧЕКБОКСОВ:**
> Отметка пунктов плана (`[x]`), критериев приёмки и изменение статуса ТЗ на `DONE` производятся **СТРОГО И ТОЛЬКО ПОСЛЕ ЯВНОГО РАЗРЕШЕНИЯ И ПРОВЕРКИ ПОЛЬЗОВАТЕЛЕМ**.
> Агент не имеет права самостоятельно ставить галочки выполнения задач до тех пор, пока пользователь лично не проверит функционал и явно не скомандует отметить чекбоксы.
