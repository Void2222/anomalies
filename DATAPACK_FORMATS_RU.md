# DATAPACK_FORMATS_RU.md — Спецификация форматов JSON и ANOM

> **Назначение документа:** Полное руководство по созданию, настройке и оркестрации аномалий через датапаки. Описывает конфигурационные файлы фаз (`.json`) и DSL-скрипты фазовых переходов (`.anom`).
> **Целевая аудитория:** Разработчики датапаков, создатели модпаков и аддонов.

---

## 📁 1. Иерархия Файлов и Определение Типов

Все файлы аномалий располагаются внутри датапака по пути:

`data/<mod_id>/anomalies/`

### 1.1. Маппинг типов и состояний из `.json`

Регистратор `AnomalyReloadListener` определяет **тип** аномалии и имя её **состояния** (`state`) по структуре пути к файлу:

* **Каноничная структура с папкой `states/` (`data/<mod>/anomalies/smart_zharka/states/idle.json`):**
* Корневая папка задает тип аномалии: `type = "smart_zharka"`.
* Имя файла внутри подпапки `states/` задает состояние: `state = "idle"`.


* **Папочная legacy-структура (`data/<mod>/anomalies/smart_zharka/idle.json`):**
* Корневая папка задает тип аномалии: `type = "smart_zharka"`.
* Имя файла без подпапки задает состояние: `state = "idle"`.


* **Однофайловая legacy-структура (`data/<mod>/anomalies/zharka.json`):**
* Имя файла становится типом аномалии: `type = "zharka"`.
* Состоянию автоматически присваивается имя `state = "idle"`.



---

### 1.2. Определение типа и валидация DSL-скриптов (`.anom`)

Загрузчик `AnomalyScriptLoader` определяет тип аномалии **строго по имени родительской папки** и валидирует корректность файловой структуры:

* **Стандарт хранения:** Файл `.anom` обязан находиться строго внутри своей папки аномалии: `data/<mod>/anomalies/<folder_name>/<folder_name>.anom`.
* **Правило именования:** Имя файла должно полностью совпадать с именем папки. Для папки `smart_zharka/` регистрируется `type = "smart_zharka"`, а загрузчик ищет файл `smart_zharka.anom`.
* **Жесткая валидация:**
* Нахождение файлов `.anom` в корне папки `anomalies/` вызовет блокирующую ошибку **CRITICAL ERROR**.
* Отсутствие файла `<folder_name>.anom` внутри именной папки вызовет **CRITICAL ERROR**.
* Если в папке обнаружено несколько файлов `.anom`, загрузчик выполнит только совпадающий `<folder_name>.anom`, а остальные проигнорирует с выводом **WARNING** в лог.



---

### Варианты структуры датапака:

1. **Простая аномалия (однофазовая / без DSL):**

```text
data/anomalies/anomalies/
├── tramplin.json       # type="tramplin", state="idle"
├── whitehole.json      # type="whitehole", state="idle"
└── voronok.json        # type="voronok",   state="idle"

```

2. **Сложная аномалия (многофазовая с DSL):**

```text
data/anomalies/anomalies/
└── smart_zharka/
    ├── smart_zharka.anom   # Главный скрипт стейт-машины (type="smart_zharka")
    └── states/             # Каталог фаз состояний
        ├── idle.json       # state="idle"
        ├── warmup.json     # state="warmup"
        ├── burst.json      # state="burst"
        └── cooldown.json   # state="cooldown"

```

## 🎲 2. Формат Диапазонов (`MinMaxRange`)

Движок поддерживает полиморфную десериализацию числовых полей `MinMaxRange`. Вы можете передавать значения двумя способами:

* **Фиксированное значение:** `"interval": 12`
* **Случайный диапазон `[min, max]`:** `"interval": [40, 80]`

> 💡 **Как это работает:** Каждая итерация тикера случайным образом выбирает значение из диапазона. Целые числа выбираются включительно (`[35, 75]`), а дробные — через равномерное распределение.

## 📄 3. Спецификация JSON-фазы (`AnomalyDefinition`)

Каждый `.json` файл описывает визуальные, звуковые, физические и боевые характеристики **одной конкретной фазы** аномалии.

### Корневая структура

```json
{
  "size": { ... },
  "particles": [ { ... } ],
  "sound": { ... },
  "trigger": { ... },
  "zones": [ { ... } ],
  "physics": { ... },
  "ignoreOtherAnomalies": true
}

```

---

### 3.1. Габариты (`size`) — `SizeConfig`

Задает физический хитбокс сущности в мире (используется для кликов мультитулом и регистрации хитбокса).

| Поле | Тип | Описание |
| --- | --- | --- |
| `width` | `float` | Ширина/диаметр хитбокса сущности в блоках. |
| `height` | `float` | Высота хитбокса сущности в блоках. |

*Пример:*

```json
"size": {
  "width": 1.6,
  "height": 0.4
}

```

---

### 3.2. Частицы (`particles`) — `List<ParticleConfig>`

Массив конфигураций спавна частиц на стороне клиента. Поддерживает оптимизацию LOD (отключается, если игрок дальше 70 блоков).

| Поле | Тип | Описание |
| --- | --- | --- |
| `type` | `String` | ResourceLocation частицы (`minecraft:flame`, `minecraft:portal`, `minecraft:campfire_cosy_smoke`). |
| `shape` | `String` | Форма объема спавна: `"SPHERE"`, `"CYLINDER"`, `"DISC"`. |
| `interval` | `MinMaxRange` | Интервал между спавном в тиках (1 тик = 0.05 сек). |
| `radius` | `double` | Радиус геометрического объема спавна. |
| `height` | `double` | Высота объема спавна (для `CYLINDER` и `DISC`). |
| `count` | `MinMaxRange` | Количество частиц, спавнящихся за один интервал. |

*Пример:*

```json
"particles": [
  {
    "type": "minecraft:flame",
    "shape": "CYLINDER",
    "interval": 1,
    "radius": 0.9,
    "height": 2.5,
    "count": [3, 12]
  }
]

```

---

### 3.3. Звук (`sound`) — `SoundConfig`

Настройка пространственного аудиоэффекта фазы.

| Поле | Тип | Описание |
| --- | --- | --- |
| `event` | `String` | Идентификатор звука (`minecraft:entity.ender_eye.launch` или кастомный `anomalies:voronok_ambient`). |
| `interval` | `MinMaxRange` | Пауза между проигрыванием звука в тиках. **Первый проигрыш происходит мгновенно на 0-м тике!** |
| `source` | `String` | Категория звука: `"BLOCKS"`, `"AMBIENT"`, `"NEUTRAL"`, `"PLAYERS"`. |
| `volume` | `float` | Громкость воспроизведения (по умолчанию `1.0`). |
| `pitch` | `float` | Высота тона / скорость звука (по умолчанию `1.0`). |

*Пример:*

```json
"sound": {
  "event": "anomalies:voronok_ambient",
  "interval": [60, 120],
  "source": "BLOCKS",
  "volume": 1.0,
  "pitch": 0.4
}

```

---

### 3.4. Сканер Поля (`trigger`) — `TriggerConfig`

*(Опционально)* Параметры обнаружения целей в окрестности. Если не указан, создается автоматически на основе максимального радиуса зон.

| Поле | Тип | Описание |
| --- | --- | --- |
| `expandRadius` | `double` | Дополнительный радиус сканирования во все стороны поверх хитбокса. |
| `interval` | `MinMaxRange` | Частота проверки наличия сущностей в тиках. |

---

### 3.5. Слои Зон (`zones`) — `List<ZoneConfig>`

**Ключевой элемент механики.** Массив физических и боевых слоев аномалии, упорядоченных **от центра к периферии**:

* **Индекс `0**` — самая внутренняя зона (эпицентр, наибольший урон/всасывание).
* **Индекс `N**` — внешние периферийные слои.

Индексы слоев (`0`, `1`, `2`) напрямую используются в `.anom` скриптах!

#### Структура объекта Зоны (`ZoneConfig`):

```json
{
  "radius": 1.3,
  "damage": {
    "innerAmount": 14.0,
    "outerAmount": 2.0,
    "fireSeconds": 3,
    "damageType": "outside_border"
  },
  "physics": {
    "pullToCenter": true,
    "pullForce": 0.12,
    "spinForce": 0.3,
    "impulseY": 0.15
  }
}

```

#### Параметры Урона (`damage` / `DamageConfig`):

| Поле | Тип | Описание |
| --- | --- | --- |
| `innerAmount` | `MinMaxRange` | Базовый/максимальный урон в эпицентре зоны. |
| `outerAmount` | `MinMaxRange` | *(Опционально)* Урон на внешней границе зоны. |
| `fireSeconds` | `int` | Длительность поджога цели в секундах (`0` — без горения). |
| `damageType` | `String` | Тип источника урона: `"fire"`, `"explosion"`, `"lightning"`, `"magic"`, `"fall"`, `"outside_border"`, `"generic"`. |

#### Параметры Физики Зоны (`physics` / `PhysicsConfig`):

| Поле | Тип | Описание |
| --- | --- | --- |
| `pullToCenter` | `boolean` | `true` — притягивать к центру аномалии; `false` — отталкивать. |
| `pullForce` | `double` | Сила притягивания/отталкивания за тик (может быть отрицательной). |
| `spinForce` | `double` | Сила тангенциального закручивания по орбите (создает эффект воронки). |
| `impulseY` | `double` | Вертикальный импульс (подброс вверх или прижатие к земле). |
| `impulseX` / `impulseZ` | `double` | Фиксированный вектор смещения по осям. |

---

### 3.6. Общие Физические Импульсы (`physics`) и Флаги

* **`physics` (`PhysicsConfig`):** Резервный фоллбэк физики, применяемый к сущности, если она находится в пределах обнаружения, но вне точных границ описанных зон.
* **`ignoreOtherAnomalies` (`boolean`):**
* `true` — аномалия игнорирует другие сущности `AnomalyEntity` (не всасывает и не наносит урон соседям).
* `false` — аномалия подминает под себя другие аномалии.



---

### 3.7. Каскадный выбор фаз (Fallback-механика)

Если стейт-машина запрашивает фазу по имени, метод `AnomalyReloadListener.get(type, state)` выполняет поиск в три шага:

1. **Точное совпадение:** Возвращает определение фазы, если имя `state` зарегистрировано для данного типа.
2. **Базовый фоллбэк (`idle`):** Если фаза не найдена, ищется базовое состояние `"idle"`.
3. **Резервный фоллбэк:** Если фазы `"idle"` нет, возвращается **первое попавшееся** загруженное состояние этого типа.

## 📜 4. Спецификация DSL-Скриптов (`.anom`)

`.anom` — это декларативный DSL для создания фазовых стейт-машин. Он связывает файлы JSON в единую цепочку состояний и управляет переходами на основе условий.

### 4.1. Общий Синтаксис

```antlr
// 1. Декларация связок "Состояние" --> "JSON"
state idle --> "idle.json";
state warmup --> "warmup.json";
state burst --> "burst.json";
state cooldown --> "cooldown.json";

// 2. Начальное состояние
initial = idle;

// 3. Блоки переходов
state <имя_состояния> {
    when <условие> -> <целевое_состояние>;
}

```

---

### 4.2. Поддерживаемые Условия (`ICondition`)

#### 1. Таймер (`timer`)

Срабатывает, когда аномалия пробыла в текущем состоянии указанное количество тиков.

```antlr
when timer(20) -> burst; // Переход через 20 тиков (1 секунда)

```

#### 2. Зоны и Игрок (`player.in_zone`, `player.entered_zone`, `player.exited_zone`)

Проверяют взаимодействие игрока со слоями аномалии (индекс слоя указывается целым числом без кавычек, например 0):

* `player.in_zone(0)` — игрок находится внутри зоны с индексом `0`.
* `player.entered_zone(0)` — игрок только что пересек границу и вошел в зону `0`.
* `player.exited_zone(0)` — игрок покинул зону `0`.

```antlr
state idle {
    when player.in_zone(0) -> warmup;
}

```

#### 3. Вероятность (`chance`)

Применяется каждый тик с указанным шансом (от `0.0` до `1.0`).

```antlr
when chance(0.05) -> random_event; // 5% шанс каждый тик

```

---

### 4.3 Логические Операторы и Альясы

Условия поддерживают стандартный порядок операций (`NOT` > `AND` > `OR`) и варианты записи:

| Операция | Ключевые слова | Символьный синтаксис |
| --- | --- | --- |
| **Логическое И** | `and` | `&&` |
| **Логическое ИЛИ** | `or` | `||` |
| **Инверсия** | `not` | `!` |

*Пример с синонимами:*

```antlr
state active {
    // Переход с использованием символьного синтаксиса
    when (player.entered_zone(0) || timer(100)) && !chance(0.2) -> cooldown;
}

```

## 🏗 5. Сквозной Эталонный Пример: "Умная Жарка"

Разберем полную цепочку взаимодействия `.anom` и `.json` файлов на примере `smart_zharka`.

### 1. Скрипт поведения (`smart_zharka.anom`)

```antlr
state idle --> "idle.json";
state warmup --> "warmup.json";
state burst --> "burst.json";
state cooldown --> "cooldown.json";

initial = idle;

// Покой -> Ждет наступания игрока на зону 0
state idle {
    when player.in_zone(0) -> warmup;
}

// Разогрев -> Гудит 1 секунду (20 тиков) -> Вспышка
state warmup {
    when timer(20) -> burst;
}

// Вспышка -> Жарит 1.5 секунды (30 тиков) -> Остывание
state burst {
    when timer(30) -> cooldown;
}

// Остывание -> Дымит 3 секунды (60 тиков) -> Возврат в Покой
state cooldown {
    when timer(60) -> idle;
}

```

### 2. Схема работы фаз:

```text
[ idle.json ]      -- (player.in_zone(0)) --> [ warmup.json ]
  • Без урона                                     • Слабый дым
  • Дым 1 раз/0.6с                                • Мелкий урон (1.0)
                                                  • Таймер 20 тиков
                                                          │
                                                          ▼
[ cooldown.json ]  <-- (timer(60 тиков)) --      [ burst.json ]
  • Остывание                                     • Огонь, лава, дым
  • Без урона                                     • Огромный урон (10.0)
  • Дым 3 секунды                                 • Поджог 8 сек
                                                  • Таймер 30 тиков

```

## ⚠️ 6. Валидация и Диагностика Ошибок

1. **Строгость путей и расширений (`validateScriptBinds`):**
* Все пути в привязках (`state burst --> "burst.json";`) указываются относительно подпапки `states/` и **обязаны** явно содержать расширение `.json`. Отсутствие `.json` вызовет блокирующую ошибку `LOGGER.error` (CRITICAL DSL ERROR).
* Если файл `burst.json` в директории `states/` отсутствует или не смог загрузиться, загрузчик выведет предупреждение `LOGGER.warn` в консоль сервера. Сервер при этом **не упадет**, а аномалия переключится на fallback-фазу (например, `idle`).

2. **Контроль структуры каталогов и `.anom` скриптов:**
* **Размещение в корне:** Размещение `.anom` файлов в корне папки `anomalies/` (вне папки конкретной аномалии) вызовет `LOGGER.error` (CRITICAL DSL ERROR).
* **Отсутствие целевого скрипта:** Если папка `anomalies/smart_zharka/` не содержит файла `smart_zharka.anom`, загрузчик выведет `LOGGER.error` и пропустит инициализацию стейт-машины для этой аномалии.
* **Дублирование файлов:** При наличии нескольких `.anom` файлов внутри одной папки будет исполнен только валидный `<folder_name>.anom`, а остальные будут проигнорированы с выводом предупреждения `LOGGER.warn`.

3. **Индексация и несовпадение зон:**
* Индексы зон указываются целыми числами без кавычек (например, `player.in_zone(1)`).
* Если в `.anom` указано `player.in_zone(1)`, а в `.json` текущей фазы массив `zones` содержит только 1 элемент (индекс `0`), предикат никогда не вернет `true`.

4. **Синтаксические ошибки `.anom`:**
* При наличии критических синтаксических ошибок ANTLR-парсера в `.anom` файле движок выведет детальный лог с указанием строки/символа в консоль, а регистратор пропустит ошибочный скрипт.

5. **Отсутствие ресурсов частиц/звуков:**
* Если в JSON-фазе указан несуществующий particle или sound event, движок подставит безопасный фоллбэк (`minecraft:flame` для частиц и тишину для звука), исключая вылет игры (Crash).
