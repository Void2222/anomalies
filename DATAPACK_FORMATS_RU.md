# DATAPACK_FORMATS_RU.md — Спецификация форматов JSON и ANOM

> **Назначение документа:** Полное руководство по созданию, настройке и оркестрации аномалий через датапаки. Описывает конфигурационные файлы фаз (`.json`), рецепты крафта (`recipes/*.json`), NBT-оверрайды и DSL-скрипты фазовых переходов (`.anom`).
> **Целевая аудитория:** Разработчики датапаков, создатели модпаков и аддонов.

---

## 📁 1. Иерархия Файлов и Определение Типов

Все файлы аномалий располагаются внутри датапака по пути:
`data/<mod_id>/anomalies/`

При загрузке все идентификаторы типов аномалий, имён фаз и рецептов **принудительно приводятся к нижнему регистру (`toLowerCase()`)**.

### 1.1. Маппинг типов и состояний из `.json`

Регистратор `AnomalyReloadListener` определяет **тип** аномалии и имя её **состояния** (`state`) по структуре пути к файлу:

* **Каноничная структура с папкой `states/` (`data/<mod>/anomalies/smart_zharka/states/idle.json`):**
* Корневая папка задает тип аномалии: `type = "smart_zharka"`.
* Имя файла внутри подпапки `states/` задает состояние: `state = "idle"`.

* **Папочная legacy-структура (`data/<mod>/anomalies/smart_zharka/idle.json`):**
* Корневая папка задает тип аномалии: `type = "smart_zharka"`.
* Имя файла без подпапки задает состояние: `state = "idle"`.

* **Однофайловая legacy-структура (`data/<mod>/anomalies/zharka.json`):**
* Имя файла становится типом аномалии: `type = "zharka"`.
* Состоянию автоматически присваивается имя `state = "idle"`.

---

### 1.2. Определение типа и валидация DSL-скриптов (`.anom`)

Загрузчик `AnomalyScriptLoader` определяет тип аномалии **строго по имени родительской папки** и валидирует корректность файловой структуры:

* **Стандарт хранения:** Файл `.anom` обязан находиться строго внутри своей папки аномалии: `data/<mod>/anomalies/<folder_name>/<folder_name>.anom`.
* **Правило именования:** Имя файла должно полностью совпадать с именем папки. Для папки `smart_zharka/` ищется файл `smart_zharka.anom`.
* **Жесткая валидация:**
* Нахождение файлов `.anom` в корне папки `anomalies/` вызовет блокирующую ошибку **CRITICAL ERROR**.
* Отсутствие файла `<folder_name>.anom` внутри именной папки вызовет **CRITICAL ERROR**.
* Если в папке обнаружено несколько файлов `.anom`, загрузчик выполнит только совпадающий `<folder_name>.anom`, а остальные проигнорирует с выводом **WARNING** в лог.

---

### 1.3. Полная структура продвинутой аномалии (со состояниями и рецептами)

```text
data/<mod_id>/anomalies/
└── smart_zharka/
    ├── smart_zharka.anom          # Главный скрипт стейт-машины (type="smart_zharka")
    ├── recipes/                   # Каталог рецептов трансмутации
    │   ├── cook_pork.json         # recipe="cook_pork"
    │   ├── make_glass.json        # recipe="make_glass"
    │   └── roast_beef.json        # recipe="roast_beef"
    └── states/                    # Каталог фаз состояний
        ├── idle.json              # state="idle"
        ├── warmup.json            # state="warmup"
        ├── burst.json             # state="burst"
        └── cooldown.json          # state="cooldown"

```

## 🎲 2. Формат Диапазонов (`MinMaxRange`)

Движок поддерживает полиморфную десериализацию числовых полей `MinMaxRange`. Вы можете передавать значения двумя способами:

* **Фиксированное значение:** `"interval": 12`
* **Случайный диапазон `[min, max]`:** `"interval": [40, 80]`

> 💡 **Как это работает:** Каждая итерация тикера случайным образом выбирает значение из диапазона. Целые числа выбираются включительно (`[35, 75]`), а дробные — через равномерное распределение. Если $min > max$, значения автоматически нормализуются.

## 📄 3. Спецификация JSON-фазы (`AnomalyDefinition`)

Каждый `.json` файл в папке состояний описывает визуальные, звуковые, физические и боевые характеристики **одной конкретной фазы** аномалии.

### Корневая структура

```json
{
  "size": { ... },
  "particles": [ { ... } ],
  "sound": { ... },
  "trigger": { ... },
  "zones": [ { ... } ],
  "physics": { ... },
  "ignoreOtherAnomalies": true
}

```

---

### 3.1. Габариты (`size`) — `SizeConfig`

Задает физический хитбокс сущности в мире (используется для кликов мультитулом и проверки AABB).

| Поле | Тип | Диапазон | Описание |
| --- | --- | --- | --- |
| `width` | `float` | `0.05` ... `64.0` | Ширина/диаметр хитбокса сущности в блоках. |
| `height` | `float` | `0.05` ... `64.0` | Высота хитбокса сущности в блоках. |

*Пример:*

```json
"size": {
  "width": 1.6,
  "height": 0.4
}

```

---

### 3.2. Частицы (`particles`) — `List<ParticleConfig>`

Массив конфигураций спавна частиц на стороне клиента. Поддерживает оптимизацию Frustum Culling и Occlusion Culling (частицы отключаются, если игрок за сплошной стеной или дальше 70 блоков).

| Поле | Тип | Описание |
| --- | --- | --- |
| `type` | `String` | ResourceLocation частицы (`"minecraft:flame"`, `"minecraft:campfire_cosy_smoke"`). При невалидном типе автоматически подставляется `minecraft:flame`. |
| `shape` | `String` | Форма объема спавна: `"SPHERE"`, `"CYLINDER"`, `"DISC"`. При некорректной строке подставляется фоллбэк `"SPHERE"`. |
| `interval` | `MinMaxRange` | Пауза между эмиссиями в тиках (`1` или `[1, 5]`). |
| `radius` | `double` | Радиус объема спавна (`0.05` ... `64.0`). |
| `height` | `double` | Высота объема спавна для `CYLINDER` и `DISC` (`0.05` ... `64.0`). |
| `count` | `MinMaxRange` | Количество частиц за одну эмиссию (`1` или `[3, 12]`). |

---

### 3.3. Звук (`sound`) — `SoundConfig`

Настройка пространственного аудиоэффекта фазы.

| Поле | Тип | Диапазон | Описание |
| --- | --- | --- | --- |
| `event` | `String` | — | Идентификатор звука (`minecraft:entity.ender_eye.launch` или кастомный `anomalies:zharka_hum`). |
| `interval` | `MinMaxRange` | $\ge 1$ | Пауза между проигрываниями в тиках. **Первый проигрыш происходит мгновенно на 0-м тике!** |
| `source` | `String` | — | Категория звука: `"BLOCKS"`, `"AMBIENT"`, `"NEUTRAL"`, `"PLAYERS"`. Фоллбэк: `BLOCKS`. |
| `volume` | `float` | `0.0` ... `10.0` | Громкость воспроизведения (по умолчанию `1.0`). |
| `pitch` | `float` | `0.0` ... `10.0` | Высота тона / скорость звука (по умолчанию `1.0`). |

---

### 3.4. Сканер Поля (`trigger`) — `TriggerConfig`

Параметры обнаружения целей в окрестности. Если не указан, создается автоматически на основе максимального радиуса зон.

| Поле | Тип | Диапазон | Описание |
| --- | --- | --- | --- |
| `expandRadius` | `double` | `0.05` ... `64.0` | Дополнительный радиус сканирования во все стороны поверх хитбокса. |
| `interval` | `MinMaxRange` | `0.05` ... `60.0` сек | Частота проверки наличия сущностей в тиках. |

---

### 3.5. Слои Зон (`zones`) — `List<ZoneConfig>`

**Ключевой элемент механики.** Массив физических и боевых слоев аномалии, автоматически сортируемый **от центра к периферии (по возрастанию радиуса)**.

* **Индекс `0**` — самая внутренняя зона (эпицентр, наибольший урон/всасывание).
* **Индекс `N**` — внешние периферийные слои.

Индексы слоев (`0`, `1`, `2`...) напрямую используются в `.anom` скриптах!

#### Структура объекта Зоны (`ZoneConfig`):

```json
{
  "radius": 1.3,
  "damage": {
    "innerAmount": 14.0,
    "outerAmount": 2.0,
    "fireSeconds": 3,
    "damageType": "fire"
  },
  "physics": {
    "pullToCenter": true,
    "pullForce": 0.12,
    "spinForce": 0.3,
    "impulseY": 0.15
  }
}

```

#### Параметры Урона (`damage` / `DamageConfig`):

| Поле | Тип | Описание |
| --- | --- | --- |
| `innerAmount` | `MinMaxRange` | Базовый урон в эпицентре зоны. |
| `outerAmount` | `MinMaxRange` | *(Опционально)* Урон на внешней границе зоны. |
| `amount` | `MinMaxRange` | *(Legacy)* Поддерживается для старых конфигов: перенаправляется в `innerAmount`, обнуляя `outerAmount`. |
| `fireSeconds` | `int` | Длительность поджога цели в секундах (`0` ... `3600`). |
| `damageType` | `String` | Тип источника урона. Движок резолвит string в ванильный тип: `"fire"` $\to$ огонь, `"lightning"` $\to$ молния, `"magic"` $\to$ магия. Все остальные идентификаторы (включая `"explosion"`, `"fall"`, `"generic"`) логируются и безопасно сбрасываются на `generic()`. |

#### Параметры Физики Зоны (`physics` / `PhysicsConfig`):

| Поле | Тип | Диапазон | Описание |
| --- | --- | --- | --- |
| `pullToCenter` | `boolean` | `true`/`false` | `true` — притягивать к центру; `false` — отталкивать. |
| `pullForce` | `double` | `-10.0` ... `10.0` | Сила притягивания/отталкивания за тик. |
| `spinForce` | `double` | `-10.0` ... `10.0` | Сила тангенциального закручивания по орбите (создает эффект воронки). Применяется только в зоной с индексом `0`. |
| `impulseY` | `double` | `-10.0` ... `10.0` | Вертикальный импульс (подброс вверх или прижатие к земле). |
| `impulseX` / `impulseZ` | `double` | `-10.0` ... `10.0` | Фиксированный вектор смещения по горизонтальным осям. |

---

### 3.6. Общие Физические Импульсы (`physics`) и Флаги

* **`physics` (`PhysicsConfig`):** Резервный фоллбэк физики, применяемый к сущности, если она находится в пределах обнаружения сканера, но вне точных границ описанных зон.
* **`ignoreOtherAnomalies` (`boolean`):**
* `true` — аномалия игнорирует другие сущности `AnomalyEntity` (не всасывает и не наносит урон соседям).
* `false` — аномалия воздействует на другие аномалии.

---

### 3.7. Каскадный выбор фаз (Fallback-механика)

Если стейт-машина запрашивает фазу по имени, метод `AnomalyReloadListener.get(type, state)` выполняет поиск в три шага:

1. **Точное совпадение:** Возвращает определение фазы, если имя `state` зарегистрировано для данного типа.
2. **Базовый фоллбэк (`idle`):** Если фаза не найдена, ищется состояние с именем `"idle"`.
3. **Резервный фоллбэк:** Если фазы `"idle"` нет, возвращается **первое попавшееся** загруженное состояние этого типа.

## 🍳 4. Спецификация Рецептов Трансмутации (`AnomalyRecipeDefinition`)

Аномалии с подключенным компонентом `RecipeProcessorComponent` способны захватывать предметы (`ItemEntity`) в эпицентре и трансмутировать их по заданным рецептам.

### 4.1. Расположение и Загрузка

Рецепты хранятся в JSON-файлах по пути:
`data/<mod_id>/anomalies/<type>/recipes/<recipe_id>.json`

Имя файла (без `.json`) является уникальным идентификатором рецепта (`recipe_id`) в рамках данного типа аномалии.

### 4.2. Структура JSON-файла Рецепта

```json
{
  "inputs": [
    {
      "item": "minecraft:porkchop",
      "count": 1
    }
  ],
  "output": {
    "item": "minecraft:cooked_porkchop",
    "count": 1
  },
  "time": 15
}

```

#### Описание полей:

| Поле | Тип | Описание |
| --- | --- | --- |
| `inputs` | `List<IngredientData>` | Массив входящих предметов, необходимых для запуска крафта. |
| `input` | `IngredientData` | *(Legacy)* Одиночный входящий предмет (для обратной совместимости). |
| `output` | `ResultData` | Предмет, создаваемый в центре аномалии по завершении крафта. |
| `time` | `int` | Время обработки в тиках (20 тиков = 1 секунда). |

##### Объект Ингредиента (`IngredientData`):

* `item` (`String`) — ResourceLocation предмета (`"minecraft:raw_iron"`).
* `count` (`int`) — Требуемое количество предметов (по умолчанию `1`).

##### Объект Результата (`ResultData`):

* `item` (`String`) — ResourceLocation создаваемого предмета.
* `count` (`int`) — Количество создаваемых предметов (по умолчанию `1`).

### 4.3. Runtime-механика работы рецептов

1. **Зона сканирования:** Аномалия ищет предметы (`ItemEntity`) в пределах самой внутренней зоны (эпицентра `zone0`). Если зоны не описаны, используется стандартный радиус в **2.5 блока**.
2. **Сессии крафта (`CraftingSession`):** При обнаружении полного набора ингредиентов создается сессия крафта, а предметы виртуально «резервируются», чтобы другие рецепты или сессии не забрали их повторно.
3. **Отмена крафта:** Если зарезервированный предмет убран из зоны или уничтожен до окончания таймера, сессия прерывается, забор отменяется, а над аномалией спавнятся частицы дыма (`minecraft:smoke`).
4. **Завершение:** По истечении `time` тиков ингредиенты списываются из стаков (пустые стаки сгорают/удаляются), а новый предмет спавнится в координатах аномалии со смещением `+0.5` по оси Y.
5. **Сохранение:** Активные сессии крафта сохраняются в NBT сущности (тег `CraftingSessions`) и корректно переживают перезапуск сервера или выгрузку чанков.

## 🛠 5. Спецификация NBT-Оверрайдов (`customOverrides`)

Каждый экземпляр аномалии в мире может иметь индивидуальные переопределения параметров, записанные в её NBT-тег `customOverrides` (например, через мультитул «Изменятор» или команды). **Приоритет NBT всегда выше, чем у JSON-файла!**

### Таблица поддерживаемых NBT-ключей:

| NBT-ключ | Тип NBT | Описываемый параметр | JSON-аналог |
| --- | --- | --- | --- |
| `width` | `Double` | Ширина хитбокса аномалии | `size.width` |
| `height` | `Double` | Высота хитбокса аномалии | `size.height` |
| `expandRadius` | `Double` | Радиус сканирования триггера | `trigger.expandRadius` |
| `triggerInterval` | `Double` | Интервал проверки триггера в тиках | `trigger.interval` |
| `soundVolume` | `Float` | Громкость звука | `sound.volume` |
| `soundPitch` | `Float` | Высота тона звука | `sound.pitch` |
| `soundIntervalMin` / `Max` | `Double` | Диапазон паузы звука | `sound.interval` |
| `particleRadius` | `Double` | Радиус спавна частиц | `particles[0].radius` |
| `particleHeight` | `Double` | Высота спавна частиц | `particles[0].height` |
| `particleIntervalMin` / `Max` | `Double` | Диапазон паузы частиц | `particles[0].interval` |
| `particleCountMin` / `Max` | `Double` | Диапазон количества частиц | `particles[0].count` |
| `zones_count` | `Integer` | Количество переопределенных зон | `zones.size()` |
| `zone_i_radius` | `Double` | Радиус зоны с индексом `i` | `zones[i].radius` |
| `zone_i_damage` | `Double` | Урон зоны с индексом `i` | `zones[i].damage` |
| `zone_i_pullForce` | `Double` | Сила тяги зоны с индексом `i` | `zones[i].physics.pullForce` |
| `zone_i_spinForce` | `Double` | Сила вращения зоны с индексом `i` | `zones[i].physics.spinForce` |
| `zone_i_impulseY` | `Double` | Подброс Y зоны с индексом `i` | `zones[i].physics.impulseY` |
| `pullToCenter` | `Byte` (bool) | Флаг притягивания к центру | `physics.pullToCenter` |
| `fireSeconds` | `Integer` | Длительность поджога | `damage.fireSeconds` |

## 📜 6. Спецификация DSL-Скриптов (`.anom`)

`.anom` — это декларативный DSL для создания фазовых стейт-машин. Он связывает файлы JSON состояний и рецептов в единую цепочку логики и управляет переходами.

### 6.1. Общий Синтаксис

```antlr
// 1. Декларация связок "Состояние" --> "JSON"
state idle --> "idle.json";
state warmup --> "warmup.json";
state burst --> "burst.json";
state cooldown --> "cooldown.json";

// 2. Декларация связок "Рецепт" --> "JSON"
recipe cook_pork --> "cook_pork.json";
recipe roast_beef --> "roast_beef.json";
recipe make_glass --> "make_glass.json";

// 3. Начальное состояние
initial = idle;

// 4. Блоки состояний
state idle {
    when player.in_zone(0) -> warmup;
}

state burst {
    // Разрешенные рецепты в этой фазе
    recipe {
        cook_pork;
        roast_beef;
        make_glass;
    }

    when timer(50) -> cooldown;
}

```

---

### 6.2. Поддерживаемые Условия (`ICondition`)

Условия применяются в блоках `when <выражение> -> <целевое_состояние>;`.

| Условие | Синтаксис | Описание |
| --- | --- | --- |
| **Таймер** | `timer(ticks)` | Срабатывает, когда аномалия находится в текущем состоянии $\ge$ `ticks` тиков (`timer(200)` = 10 секунд). |
| **Вероятность** | `chance(val)` | Вычисляет шанс от `0.0` (0%) до `1.0` (100%) каждый тик. Пример: `chance(0.05)` = 5% шанс за тик. |
| **Игрок в зоне** | `player.in_zone(index)` | `true`, если игрок находится внутри зоны с указанным **числовым индексом**. |
| **Вход игрока** | `player.entered_zone(index)` | `true` в тик, когда игрок пересек границу зоны с указанным **числовым индексом**. |
| **Выход игрока** | `player.exited_zone(index)` | `true` в тик, когда игрок покинул зону с указанным **числовым индексом**. |

> ⚠️ **ВАЖНОЕ ПРАВИЛО ИНДЕКСАЦИИ ЗОН:**
> Индекс зоны в `player.in_zone(...)` и эвентах принимает **строго целочисленный индекс** (`0`, `1`, `2`...), соответствующий отсортированному порядку зон! Передача строк или несуществующих индексов приведет к тому, что условие никогда не исполнится.

---

### 6.3. Логические Операторы и Синтаксис

Условия поддерживают стандартный приоритет операций (`NOT` > `AND` > `OR`), группировку скобками `(...)` и текстовые или символьные синонимы:

| Операция | Ключевые слова | Символьный синтаксис |
| --- | --- | --- |
| **Логическое И** | `and` | `&&` |
| **Логическое ИЛИ** | `or` | ` |
| **Инверсия** | `not` | `!` |

*Пример с группировкой:*

```antlr
state active {
    when (player.entered_zone(0) || timer(100)) && !chance(0.2) -> cooldown;
}

```

### 6.4. Декларация Рецептов в DSL

Рецепты объявляются вверху `.anom` файла и подключаются внутри блоков `state`:

1. **Глобальное связывание:**
   `recipe <recipe_id> --> "<path_to_recipe>.json";`
2. **Подключение к фазе:**

```antlr
state burst {
    recipe {
        cook_pork;
        roast_beef;
        make_glass;
    }

    when timer(50) -> cooldown;
}

```

> 💡 **Правило безопасности:** Если в состоянии аномалии не описан блок `recipe { ... }`, аномалия в этой фазе **не будет** перерабатывать предметы, даже если файлы рецептов присутствуют на диске.

### 7.4. Скрипт стейт-машины (`smart_zharka.anom`)

```antlr
// 1. Привязка фаз к JSON-файлам
state idle --> "idle.json";
state warmup --> "warmup.json";
state burst --> "burst.json";
state cooldown --> "cooldown.json";

// 2. Привязка рецептов
recipe cook_pork --> "cook_pork.json";
recipe roast_beef --> "roast_beef.json";
recipe make_glass --> "make_glass.json";

// 3. Стартовая фаза
initial = idle;

// 4. Логика переходов и разрешения рецептов
state idle {
    when player.in_zone(0) -> warmup;
}

state warmup {
    when timer(20) -> burst;
}

state burst {
    recipe {
        cook_pork;
        roast_beef;
        make_glass;
    }
    when timer(50) -> cooldown;
}

state cooldown {
    when timer(60) -> idle;
}

```

## ⚠️ 8. Валидация и Диагностика Ошибок

1. **Строгость путей и расширений (`validateScriptBinds`):**
* Все пути в привязках состояний и рецептов **обязаны** явно содержать расширение `.json` (например, `state idle --> "idle.json";`). Отсутствие `.json` вызовет блокирующую ошибку `CRITICAL DSL ERROR` в логе сервера.
* Если файл `.json` отсутствует по указанному пути, загрузчик выведет `LOGGER.warn`. Игра не упадет, а аномалия применит каскадный фоллбэк на фазу `idle`.

2. **Контроль структуры каталогов:**
* Размещение `.anom` файлов в корне папки `anomalies/` вызовет `CRITICAL DSL ERROR`.
* Если папка `smart_zharka/` не содержит файла `smart_zharka.anom`, инициализация стейт-машины будет пропущена.
* При наличии нескольких `.anom` файлов в одной папке исполняется только совпадающий с именем папки, а остальные игнорируются с выводом `LOGGER.warn`.

3. **Несовпадение индексов зон:**
* Если в `.anom` указано `player.in_zone(1)`, а в `.json` текущей фазы описана только 1 зона (с индексом `0`), предикат никогда не вернет `true`.

4. **Синтаксические ошибки `.anom`:**
* Ошибки в грамматике ANTLR выводятся в консоль сервера с указанием точной строки и символа, а проблемный скрипт снимается с регистрации.

5. **Безопасность фоллбэков:**
* Несуществующие частицы подменяются на `minecraft:flame`.
* Неизвестные типы урона сбрасываются в `generic()`.
* Некорректные имена аудиокатегорий сбрасываются в `SoundSource.BLOCKS`.
