# Anomalies Mod

Мод добавляет гибкую, событийно-ориентированную систему многофазовых аномалий с собственным DSL-языком скриптов (`.anom`) и возможностью точечной настройки через JSON-датапаки и NBT-теги[cite: 3, 4, 5]. Каждая аномалия представляет собой стейт-машину с динамической сменой фаз, слоев воздействия, физики, визуальных эффектов и урона[cite: 3, 4].

---

## 🛠 Основные возможности

* **DSL-скрипты и Стейт-машины (`.anom`):** Поведение аномалий описывается декларативным языком на базе ANTLR-парсера[cite: 3, 4]. Поддерживаются таймеры (`timer`), вероятности (`chance`), отслеживание игрока в зонах (`player.in_zone`) и логические операторы (`&&`, `||`, `!`)[cite: 3, 4].
* **JSON-шаблоны фаз и NBT-оверрайды:** Каждая фаза аномалии описывается отдельным JSON-файлом в подпапке `states/`[cite: 3, 4]. Базовые параметры можно на лету переопределять для конкретной сущности в мире через NBT-тег `customOverrides`[cite: 4, 5].
* **Многослойная физика и зоны:** Настройка радиусов, притяжения/выталкивания, тангенциального вращения, вертикальных импульсов и горения для каждого слоя отдельно[cite: 3, 5].
* **Оптимизация (LOD):**
  * **Сервер:** Триггерный сканер переходит в спящий режим, если в радиусе 48 блоков нет игроков[cite: 4, 5].
  * **Клиент:** Двухуровневое отсечение частиц (Frustum Culling + Occlusion Culling за стенами) и остановка рендера дальше 70 блоков[cite: 4, 5].
* **API для разработчиков:** Расширяемый набор отменяемых событий Forge для интеграции кастомных реакций и поведения[cite: 3, 5].

## 📁 Структура Датапака

Аномалии регистрируются по каноничному пути `data/<mod_id>/anomalies/<folder_name>/`[cite: 3, 4]:

```text
data/<mod_id>/anomalies/
└── smart_zharka/
    ├── smart_zharka.anom   # Главный DSL-скрипт логики (type = "smart_zharka")
    └── states/             # Каталог конфигураций фаз
        ├── idle.json       # Фаза покоя
        ├── warmup.json     # Фаза разогрева
        └── burst.json      # Фаза выброса

```

## 🔧 Мультитул Администратора

Инструмент `AnomalyMultitoolItem` предназначен для настройки и управления аномалиями в мире. Режимы переключаются комбинацией **Shift + ПКМ по воздуху**:

* **ANALYZE (Анализ)**
* **Управление:** ПКМ по аномалии.

* **Назначение:** Выводит в чат характеристики аномалии по всем зарегистрированным фазам и подсвечивает локальные NBT-оверрайды `[NBT]`.

* **MODIFY (Изменение)**
* **Управление:** ПКМ — сессия / Shift+ПКМ — сброс.

* **Назначение:** Запускает пошаговое изменение параметров через чат или полностью сбрасывает оверрайды до значений из JSON.

* **RELOCATE (Перемещение)**
* **Управление:** ПКМ — захват / ЛКМ по блоку / Shift+ПКМ.

* **Назначение:** Переносит аномалию на выбранный блок или сдвигает ее по координатам через чат (`dx dy dz`).

* **DELETE (Удаление)**
* **Управление:** ЛКМ по аномалии / Shift+ЛКМ.

* **Назначение:** Безопасное удаление с 5-секундным подтверждением от случайного клика или мгновенное удаление с зажатым Shift.

## 📜 Команды

* `/anomaly create <type>` — создает аномалию указанного типа на координатах игрока (с автокомплитом типов).

* `/anomaly state set <state>` — принудительно переключает текущую фазу аномалии под прицелом (для удобства отладки эффектов и скриптов).


* `/anomaly ignore <player> <true|false>` — добавляет или удаляет игрока из списка защиты от физики и урона аномалий.

## 💻 API для Разработчиков

Все события публикуются на `MinecraftForge.EVENT_BUS` и могут быть отменены (`@Cancelable`):

* `AnomalyTriggerEvent` — вход сущности в область действия аномалии.

* `AnomalyDamageEvent` — расчет и нанесение урона сущности.

* `AnomalyPhysicsEvent` — вычисление и применение векторов притяжения/вращения.

* `AnomalyZoneTransitionEvent` — пересечение сущностью границ между внутренними слоями зон.

* `AnomalyItemInteractEvent` — попадание выпадающих предметов (`ItemEntity`) в зону аномалии.
